## Hell Let Loose Community RCON (CRCON)

**Copyright (c) 2020 Julien Marechal · MIT** · <https://github.com/MarechJ/hll_rcon_tool>
Full licence text: `third_party/crcon/LICENSE`.

This project serves CRCON's public API byte for byte, so a tool built for CRCON works against it
unchanged. Doing that meant carrying over parts of CRCON itself, in three forms:

### 1. Verbatim source: `third_party/crcon/`

Six unmodified files, kept as the evidence behind the API-parity claims. Not imported by any
build. Details: `third_party/crcon/README.md`.

### 2. Data extracted from CRCON's source

| File | From CRCON |
|---|---|
| `packages/maps/src/crcon-catalogue.ts` | the map catalogue: tags, short names, orientation, factions (`rcon/maps.py`) |
| `packages/maps/src/crcon-layer-data.ts` | the map and layer catalogue, `MAPS` and `LAYERS` (`rcon/maps.py`, v12.3.0), generated by `packages/maps/scripts/extract-crcon-catalogue.py` |

### Not CRCON's code

Everything else that works with CRCON is written here and is under this repository's licence:
importing a CRCON database or backup, the `crcon-bridge` connection, reading CRCON's API, and
answering on the same endpoint names, JSON shapes and message tokens. Matching an interface is
not copying the code behind it. Where a file does carry CRCON's code, it is in the tables above.

## Consulted, nothing copied

These shaped the work, but none of their code or text is in this repository:

- **orjson** (ijl) and **zmij** (David Tolnay): their source settled exactly how CRCON's API writes
  floats and dates. `apps/api/src/crcon-json.ts` produces the same output with its own code.
- **Python**: the behaviour of `urllib`'s unquoting, `repr` and `round` that CRCON's answers depend
  on, reproduced with this project's own code in `crcon-json.ts` and `crcon-http.ts`.
- **hll_crcon_live_topstats** by ElGuillermo (MIT): the idea of sending every player the
  match-end winners list (Game rewards, Top stats). The idea only.
